# OA 客服 Agent 需求规格说明

## 1. 项目目标

在现有 OA 系统中新增客服 Agent，帮助用户通过对话查询项目 OA 进度、理解当前流程状态，并获得下一步操作指引。

Agent 必须严格遵守账号权限边界。普通账号只能读取与当前登录用户相关的项目内容；管理员账号只有在现有权限系统允许时，才能检索全部项目数据库。

## 2. 使用入口

1. 全局独立聊天页面。
2. 项目详情页或项目清单页内嵌聊天入口。
3. 用户在项目详情页提问时，默认带入当前项目上下文。

## 3. 功能范围

Agent 支持以下能力：

1. OA 系统使用指导。
2. 按项目名称、项目编号、客户名称进行模糊检索。
3. 返回候选项目列表，最多 10 个。
4. 查询项目基础信息。
5. 查询项目 OA 清单与流程状态。
6. 查询审批记录，并允许展示审批意见原文。
7. 查询附件元信息。
8. 查询评论、流程日志、任务和待办。
9. 根据当前用户角色、流程节点、历史审批意见和待办状态，给出下一步操作建议。

## 4. 禁止范围

Agent 不允许执行以下行为：

1. 读取任何附件正文，包括 PDF、Word、Excel、图片和压缩包内容。
2. 查询当前账号无权限访问的项目。
3. 将未授权数据发送给 DeepSeek。
4. 代替用户提交、审批、修改、上传或删除。
5. 让大模型直接访问数据库。
6. 根据用户提示词绕过后端权限校验。
7. 输出与当前用户无关的项目内容。

## 5. 权限规则

普通用户可访问项目的条件：

1. 当前用户是项目负责人。
2. 当前用户是项目协作人或参与人。
3. 当前用户是项目审批人。

管理员权限规则：

1. 不直接依赖用户表角色字段以外的临时判断。
2. 通过现有权限系统识别管理员能力。
3. 拥有管理员权限的账号可在 Agent 中检索全部项目数据库。

所有权限判断必须发生在后端业务代码中，不能交给 LLM 判断。

## 6. 项目检索规则

项目检索字段：

1. 项目名称。
2. 项目编号。
3. 客户名称。

检索流程：

1. 先识别当前登录账号。
2. 判断当前账号是否拥有管理员权限。
3. 普通用户先按项目负责人、项目成员、项目审批人关系过滤项目。
4. 在已授权项目范围内执行模糊检索。
5. 命中唯一项目时进入项目问答。
6. 命中多个项目时返回最多 10 个候选项目。
7. 未命中时不暴露无权限项目是否存在，只提示用户更换关键词或确认权限。

## 7. 附件规则

Agent 只能读取附件元信息：

1. 附件名称。
2. 附件类型。
3. 上传人。
4. 上传时间。
5. 所属项目。
6. 所属业务模块。
7. 是否存在附件。

Agent 不读取、不解析、不总结任何附件正文内容。

## 8. 会话规则

1. 保存当前会话上下文，支持连续追问。
2. 用户退出登录时清除当前会话历史。
3. 暂不要求长期保存完整对话记录。

## 9. 审计规则

只记录敏感数据访问行为，粒度到项目模块级别。

需要审计的模块：

1. 审批记录。
2. 附件。
3. 评论。
4. 任务和待办。

审计日志不记录完整问答内容。

## 10. LLM 接入

1. 接入 DeepSeek 官方 API。
2. 后端负责身份识别、权限过滤和数据查询。
3. DeepSeek 只基于已授权上下文生成简洁回答。
4. 模型调用保留供应商抽象，便于后续替换。

## 11. 回答风格

Agent 回答采用简洁流程型，优先包含：

1. 当前项目状态。
2. 当前流程节点。
3. 当前处理人或责任角色。
4. 用户下一步应该做什么。
5. 对应 OA 操作入口或页面路径。
6. 必要时提示权限不足或信息缺失。

## 12. 分步实施与验收

### 步骤 1：需求规格落档

产出：

1. 本需求规格说明。
2. 明确 Agent 功能边界、权限边界、附件边界和审计边界。

验收标准：

1. 文档包含入口、功能、禁止范围、权限、检索、附件、会话、审计、LLM 和回答风格。
2. 文档明确 Agent 不读取附件正文。
3. 文档明确 Agent 不执行写操作。
4. 文档明确所有数据进入 DeepSeek 前必须完成后端权限过滤。

### 步骤 2：接口设计与最小后端路由

产出：

1. Agent 发送消息接口。
2. 候选项目检索接口。
3. 当前会话读取与清除接口。
4. 项目上下文选择接口。

验收标准：

1. 每个接口有明确请求和响应结构。
2. 每个接口必须登录后访问。
3. 每个接口明确权限校验点。
4. 敏感模块访问预留审计触发点。

### 步骤 3：数据库访问规则

产出：

1. 项目权限过滤查询。
2. 项目基础信息读取。
3. 流程状态、审批记录、附件元信息、评论、任务和待办读取。

验收标准：

1. 普通用户不能查询到无关项目。
2. 管理员可查询全量项目。
3. 附件查询只返回元信息，不返回正文。

### 步骤 4：权限校验规则

产出：

1. 普通用户项目访问判断。
2. 管理员访问判断。
3. 项目页上下文权限校验。
4. 权限不足时的统一回复策略。

验收标准：

1. 权限判断不依赖 LLM。
2. 权限不足时不暴露项目是否存在。
3. 所有传入 LLM 的数据均已完成权限过滤。

### 步骤 5：Prompt 与 DeepSeek 封装

产出：

1. System Prompt。
2. 数据上下文模板。
3. 候选项目、权限不足、下一步操作、附件限制等回复模板。
4. DeepSeek 官方 API 调用封装。

验收标准：

1. Prompt 明确禁止编造项目状态。
2. Prompt 明确禁止读取附件正文。
3. Prompt 输出保持简洁流程型。
4. DeepSeek 不接触任何未授权数据。

### 步骤 6：审计日志设计与实现

产出：

1. 敏感模块访问日志模型。
2. 审计写入服务。
3. 审批记录、附件、评论、任务和待办访问审计。

验收标准：

1. 审计只记录敏感模块访问。
2. 审计粒度到项目模块级别。
3. 不记录完整问答内容。
4. 能追溯用户在什么时间访问了哪个项目的哪个敏感模块。

### 步骤 7：前端入口与会话体验

产出：

1. 全局 Agent 页面。
2. 项目详情页内嵌入口。
3. 项目页默认带入当前项目上下文。
4. 用户退出登录时清理当前会话。

验收标准：

1. 全局入口可发起会话。
2. 项目详情页提问默认使用当前项目。
3. 候选项目列表可选择。
4. 退出登录后会话上下文清除。

### 步骤 8：整体场景验收

验收场景：

1. 普通用户查询自己参与的项目。
2. 普通用户查询无权限项目。
3. 管理员查询任意项目。
4. 用户输入模糊项目名称并选择候选项目。
5. 项目页默认带入当前项目。
6. 用户询问附件内容时，Agent 明确说明不能读取正文。
7. 用户询问下一步操作时，Agent 返回当前节点和操作入口。
8. 用户退出登录后会话清除。
