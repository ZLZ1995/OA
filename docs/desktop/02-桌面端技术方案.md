# 中勤评估业务OA系统桌面端技术方案

## 1. 文档目标
本文档说明桌面端一期的总体技术结构、模块边界、配置存储、通知链路、更新链路、安全策略与关键实现约束，用于指导实际开发落地。

## 2. 总体架构
桌面端采用 Electron 独立工程，以远程加载现有 OA Web 前端为主，业务逻辑继续保留在现有前后端仓库中。

整体结构如下：
- Electron 主进程：负责窗口、托盘、下载、更新、通知、开机自启、本地配置
- Preload：向页面暴露受控的桌面能力桥接接口
- Web OA：继续负责登录、路由、业务处理、权限判断、项目流转
- OA 后端：继续负责 API、WebSocket、通知数据、权限校验

## 4. 模块职责
### 4.1 主入口
`src/main/index.ts`
- 获取单实例锁
- 初始化配置服务
- 创建主窗口
- 初始化托盘、菜单、自动更新、通知监听
- 注册应用退出与恢复逻辑

### 4.2 窗口模块
`src/main/windows.ts`
- 创建主窗口
- 创建设置窗口
- 创建外链窗口
- 创建自定义桌面提醒窗口
- 恢复窗口大小与位置

### 4.3 配置模块
`src/main/config.ts`
- 读取和写入本地配置
- 提供默认值合并
- 校验地址格式与目录合法性
- 区分管理员可编辑配置与普通用户可编辑配置

### 4.4 菜单与托盘
`src/main/menu.ts`
- 定义顶部菜单
- 提供“自定义下载目录”“检查更新”“设置”等入口

`src/main/tray.ts`
- 定义托盘图标与右键菜单
- 支持从托盘恢复主窗口或退出应用

### 4.5 下载模块
`src/main/downloads.ts`
- 监听下载事件
- 始终弹出保存位置选择框
- 使用配置中的默认下载目录作为对话框默认路径

### 4.6 更新模块
`src/main/updater.ts`
- 启动时自动检查更新
- 处理普通更新与关键更新
- 管理更新下载、安装提示与失败重试

### 4.7 通知模块
`src/main/notifications.ts`
- 建立通知 WebSocket 连接
- 拉取通知详情
- 过滤是否属于待办提醒
- 触发右下角提醒弹窗

### 4.8 深链模块
`src/main/deep-link.ts`
- 将通知详情转换为 OA 内部目标路由
- 统一处理“立即处理”跳转
- 登录失效时生成带 `redirect` 的登录页地址

### 4.9 安全模块
`src/main/security.ts`
- 统一定义 BrowserWindow 安全参数
- 控制外链窗口权限
- 限制导航与新窗口行为

## 5. 主窗口加载策略
主窗口默认加载：
- 前端地址：`https://zhongqinoa01.com/`

构造 URL 的规则：
- 主窗口使用前端地址作为基础地址。
- 通知跳转与登录重定向仅修改其路径与查询参数。
- 后端地址单独用于 API 健康检查、通知详情拉取、更新元数据请求等桌面侧任务。

## 6. 本地配置存储
### 6.1 存储位置
配置文件保存在 Electron 用户数据目录，例如：

```text
%APPDATA%/中勤评估业务OA系统/config.json
```

### 6.2 建议配置结构

```json
{
  "frontendUrl": "https://zhongqinoa01.com/",
  "backendUrl": "https://zhongqinoa.zeabur.app",
  "downloadDefaultDir": "",
  "autoStartEnabled": true,
  "closeBehavior": "ask",
  "rememberCloseChoice": false,
  "windowBounds": {
    "width": 1440,
    "height": 900,
    "x": 120,
    "y": 80
  },
  "lastWorkspaceUrl": "",
  "updateChannel": "stable"
}
```

### 6.3 配置权限控制
- 普通用户可修改：
  - `downloadDefaultDir`
  - `autoStartEnabled`
  - `closeBehavior`
  - `rememberCloseChoice`
- 仅管理员可修改：
  - `frontendUrl`
  - `backendUrl`

实现约束：
- 桌面端在允许修改 OA 地址前，需通过当前登录态调用 `/api/v1/auth/me` 判断是否包含 `ADMIN` 角色。
- 地址配置界面即使被普通用户打开，也必须显示为只读或不可提交状态。

## 7. 安全策略
主窗口与外链窗口均应采用严格配置：
- `nodeIntegration: false`
- `contextIsolation: true`
- `sandbox: true`
- `enableRemoteModule: false`
- 不向远程页面直接暴露文件系统与系统命令能力

其他约束：
- 主窗口只允许加载配置中的前端地址
- 外链窗口应采用独立 BrowserWindow，不允许复用主窗口 WebContents
- 阻止未知域名或危险协议导航
- 桌面桥接接口通过 preload 精确暴露，不做全量透传

## 8. 下载方案
下载实现采用 Electron 的下载拦截：
- 监听主窗口 `session` 的下载事件
- 每次下载时弹出 `save dialog`
- 默认目录使用本地配置中的 `downloadDefaultDir`
- 用户取消保存则视为取消下载

原因：
- 与“每次都弹窗确认”的需求一致
- 不依赖网页侧自行决定文件保存路径
- 对导出 Excel、培训手册、合同附件等下载路径统一生效

## 9. 开机自启与关闭行为
### 9.1 开机自启
- 使用 Electron `app.setLoginItemSettings`
- 默认开启
- 用户关闭后写入本地配置并同步系统设置

### 9.2 关闭行为
- 点击窗口关闭按钮时拦截默认退出
- 若 `rememberCloseChoice=false`，弹出确认窗口：
  - 退出应用
  - 最小化到托盘
- 若用户已记住选择，则直接执行对应行为

## 10. 自动更新方案
### 10.1 技术选型
- 打包器：`electron-builder`
- Windows 安装器：NSIS
- 更新客户端：`electron-updater`

### 10.2 更新元数据
建议更新服务提供两层信息：
- `latest.yml`
  用于 `electron-updater` 标准更新机制
- `release.json`
  用于额外标识 `releaseLevel`，区分 `normal` 与 `critical`

示例：

```json
{
  "version": "1.2.0",
  "releaseLevel": "critical",
  "notes": "修复关键流程跳转与通知提醒问题",
  "publishedAt": "2026-06-26T10:00:00Z"
}
```

### 10.3 行为规则
- 应用启动后自动检查更新
- 若存在新版本：
  - `normal`：允许“立即更新”或“稍后”
  - `critical`：必须更新后才能继续进入主业务
- 下载完成后提示重启安装

## 11. 通知链路方案
### 11.1 数据来源
现有后端已提供：
- WebSocket：`/api/v1/ws/notifications`
- 通知详情：`/api/v1/notifications/{id}`
- 通知统计与列表接口
- 工作台待办项目接口：`/api/v1/workbench`

### 11.2 监听流程
建议桌面端采用以下链路：
1. 从当前登录态中获取 `access_token`
2. 使用后端地址连接 WebSocket
3. 收到 `notification_created` 事件后，根据 `notification_id` 拉取通知详情
4. 对通知详情进行待办过滤
5. 如需进一步判定“进入项目”的待办语义，可拉取 `/api/v1/workbench`，在 `todo_projects` 中定位对应项目
6. 生成桌面提醒内容并展示

### 11.3 提醒过滤规则
仅当满足以下条件时允许弹窗：
- `popup_flag === true`
- `is_read === false`
- `process_status !== "PROCESSED"`
- 属于待办/需要处理类消息
- 存在可跳转目标

说明：
- 第一版优先过滤 `message_type=REMINDER` 且具备项目处理语义的通知。
- 若后端后续将“待办类工作流消息”统一纳入提醒范围，可在不改路由协议的前提下扩展。

### 11.4 提醒呈现方式
建议采用 Electron 自定义右下角小窗，而不是仅依赖系统原生通知。

原因：
- 便于固定展示“关闭”和“立即处理”两个动作
- 便于控制样式、排队和点击行为
- 更接近办公软件的桌面提示体验

## 12. 跳转与登录恢复
桌面端“立即处理”必须复用现有 Web OA 的登录与路由行为：
- 登录态有效：直接加载目标路由
- 登录态失效：加载 `/login?redirect=目标路由`
- 登录成功后由现有登录页逻辑继续跳转

这意味着桌面端不负责实现业务页权限绕过，而只负责构造正确路由。

## 13. 外链处理
根据当前需求，外部链接允许在 App 内打开。

实现建议：
- 使用单独的 BrowserWindow 打开外链
- 外链窗口不继承主窗口的业务桥接接口
- 外链窗口同样使用安全隔离配置
- 后续如需限制域名，可在白名单中控制

## 14. 实施顺序建议
1. 建立 Electron 工程骨架与打包流程
2. 实现主窗口、托盘、关闭行为、窗口状态记忆
3. 接入本地配置与管理员地址配置
4. 接入下载拦截与默认目录
5. 接入自动更新
6. 接入通知监听与桌面提醒
7. 接入“立即处理”深链跳转
8. 完成联调与验收
