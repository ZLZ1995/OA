# 中勤评估业务OA系统桌面端更新发布约定

## 1. 文档目标
本文档定义桌面端 Windows 安装包的版本规则、更新分级、发布产物、元数据格式与发布流程，用于支撑启动时自动检查更新的实现。

## 2. 发布对象
- 发布平台：Windows
- 发布形态：`.exe` 安装包
- 安装器建议：NSIS
- 更新方式：应用启动时自动检查

## 3. 版本号规则
建议采用语义化版本号：

```text
主版本号.次版本号.修订号
```

说明：
- 主版本号：存在重大行为变化、兼容性变更或关键交互重构
- 次版本号：新增功能、增强能力
- 修订号：问题修复、细节优化

示例：
- `1.0.0`
- `1.1.0`
- `1.1.3`

## 4. 更新分级
桌面端更新分为两类：

### 4.1 普通更新
- 允许用户选择“立即更新”或“稍后”
- 适用于：
  - 常规功能增强
  - 非阻断性 bug 修复
  - 体验优化

### 4.2 关键更新
- 不允许跳过
- 用户必须更新完成后才能继续使用当前版本
- 适用于：
  - 关键安全修复
  - 严重业务流程错误修复
  - 服务端接口兼容性断裂
  - 桌面端存在致命问题且无法继续容忍

## 5. 发布产物
每次发布至少产出：
- Windows 安装包：`.exe`
- `latest.yml`
- `release.json`
- 差分更新文件（如启用 blockmap，可选）

建议发布目录结构：

```text
/desktop-updates/win/stable/
  latest.yml
  release.json
  zhongqin-oa-setup-1.0.0.exe
  zhongqin-oa-setup-1.0.0.exe.blockmap
```

说明：

1. 软件安装后对用户展示的应用名称仍可使用中文
2. 更新源中的安装包与 blockmap 文件名统一使用 ASCII

### 5.1 blockmap 容错规则
若 `latest.yml`、`release.json` 与完整安装包 `.exe` 均已发布成功，则允许在 `.blockmap` 缺失时继续上线。

此时：

1. 客户端仍可发现新版本
2. 客户端仍可执行整包下载更新
3. 仅差量更新能力不可用

## 6. 元数据约定
### 6.1 `latest.yml`
由 `electron-builder` 生成，供 `electron-updater` 使用。

### 6.2 `release.json`
由发布流程额外提供，至少包含：

```json
{
  "version": "1.0.0",
  "releaseLevel": "normal",
  "notes": "修复下载目录与通知弹窗问题",
  "publishedAt": "2026-06-26T10:00:00Z",
  "minSupportedVersion": "1.0.0"
}
```

字段说明：
- `version`：目标版本号
- `releaseLevel`：`normal` 或 `critical`
- `notes`：更新说明
- `publishedAt`：发布时间
- `minSupportedVersion`：最小受支持版本，用于辅助判断是否强制更新

## 7. 更新检测规则
应用启动后执行：
1. 读取当前本地版本号
2. 请求远端更新元数据
3. 比较版本号
4. 若远端版本更高，则进入更新处理流程

### 7.1 普通更新处理
- 弹出更新提示
- 用户可选择：
  - 立即更新
  - 稍后再说

### 7.2 关键更新处理
- 弹出强制更新提示
- 禁止直接继续进入主业务页
- 用户仅可：
  - 立即下载并安装更新
  - 退出应用

## 8. 发布流程约定
建议发布流程如下：
1. 更新桌面端版本号
2. 构建 Windows 安装包
3. 生成 `latest.yml`
4. 维护 `release.json`
5. 上传发布产物到更新目录
6. 使用测试环境验证更新链路
7. 再面向正式用户开放

## 9. 测试要求
每次发布前至少验证：
- 无更新时客户端静默启动
- 普通更新能提示且允许稍后
- 关键更新能阻断旧版本继续进入
- 更新下载完成后可正确重启安装
- 更新失败时能给出明确提示

## 10. 回滚约定
若新版本发布后发现严重问题：
- 应保留上一稳定版安装包与 `latest.yml` 对应产物
- 可通过回退 `release.json` 与 `latest.yml` 指向的版本恢复更新入口
- 若关键问题已扩散，应发布更高版本的修复包，而非长期保留异常版本

## 11. 文案约定
更新提示建议遵循以下口径：
- 普通更新：有新版本可用，是否现在更新
- 关键更新：当前版本已不再支持，请先更新后继续使用
- 更新失败：更新下载失败，请稍后重试

## 12. 一期约束
- 一期只做 Windows 更新链路
- 一期不做代码签名
- 一期默认单更新通道 `stable`
