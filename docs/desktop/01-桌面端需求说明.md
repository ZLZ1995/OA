# 中勤评估业务OA系统桌面端需求说明

## 1. 文档目的
本文档用于固化 Windows 桌面端的一期建设范围、约束条件、核心交互与非功能要求，作为后续技术方案、开发实现、联调测试与验收的统一依据。

## 2. 产品定位
- 产品名称：中勤评估业务OA系统
- 窗口标题：中勤评估业务OA系统
- 当前交付平台：Windows
- 后续扩展平台：macOS（本期仅预留结构，不交付）
- 部署形态：Electron 桌面客户端，连接现有 Web OA 服务，不内置本地 FastAPI 后端

## 3. 默认服务地址
- 前端默认地址：`https://zhongqinoa01.com/`
- 后端默认地址：`https://zhongqinoa.zeabur.app`

说明：
- 桌面端默认加载前端地址。
- API、WebSocket、更新元数据等服务优先使用后端地址或后端挂载的更新服务地址。

## 4. 一期建设目标
一期目标是在不改变现有 OA 核心业务逻辑的前提下，将 Web OA 封装为可安装、可常驻、可更新、可提醒的 Windows 桌面应用，补齐以下桌面能力：
- Windows `.exe` 安装包
- 启动时自动检查更新
- 系统托盘常驻
- 开机自启
- 窗口关闭时支持退出或转后台运行
- 记住窗口大小和位置
- 文件下载每次弹窗选择保存位置
- 顶部菜单支持用户设置默认下载目录
- 管理员可配置 OA 前后端地址
- 接收待办类新消息并在桌面右下角弹出提醒
- 点击提醒的“立即处理”后跳转到对应业务页面

## 5. 非目标范围
本期不包含以下内容：
- 不做离线单机版
- 不内置 Python 运行时、SQLite 数据文件或本地业务服务
- 不做 Windows 代码签名
- 不做提醒声音
- 不做 macOS 安装包交付
- 不改造现有 OA 业务权限模型

## 6. 用户角色与权限
### 6.1 普通用户
- 可登录、使用 OA 主业务
- 可设置默认下载目录
- 可查看和修改开机自启状态
- 可设置关闭行为
- 不可修改 OA 前端地址与后端地址

### 6.2 管理员用户
- 具备普通用户全部能力
- 可配置 OA 前端地址与后端地址
- 可恢复默认 OA 地址配置

## 7. 核心功能需求
### 7.1 启动与主窗口
- 双击桌面应用后打开主窗口。
- 主窗口默认加载 OA 登录页或恢复上次有效页面。
- 应用标题显示“中勤评估业务OA系统”。
- 应保存并恢复上次窗口大小和位置。
- 如果上次窗口位置超出当前显示器可见区域，应自动回退到当前主屏可见范围。

### 7.2 开机自启
- 应用默认开启开机自启。
- 用户可在设置中手动关闭开机自启。
- 下次重启系统后应按用户最后一次设置生效。

### 7.3 托盘与关闭行为
- 应用支持托盘常驻。
- 托盘菜单至少包含：显示主窗口、打开 OA、检查更新、设置、退出。
- 用户点击主窗口关闭按钮时，应弹出确认：
  - 彻底退出应用
  - 最小化到托盘并继续后台运行
- 后台运行时，通知监听和桌面提醒继续工作。

### 7.4 地址配置
- 默认使用预设的前端与后端地址。
- 仅管理员可修改 OA 地址配置。
- 地址配置修改后应持久化保存，并在应用重启后继续生效。
- 应提供“恢复默认地址”入口。
- 地址无效或不可达时，应有清晰错误提示，并允许用户返回默认配置。

### 7.5 文件下载
- 所有下载操作均应弹出保存位置选择框。
- 顶部菜单中应提供“自定义下载目录”功能。
- 自定义下载目录只作为默认打开目录，不得取消每次保存前的用户确认。

### 7.6 外部链接
- 外部链接允许在桌面 App 内打开。
- 外链不得接管主 OA 窗口的桌面权限。
- 外链打开后应与 OA 主窗口保持安全隔离。

### 7.7 自动更新
- 应用启动时自动检查更新。
- 更新分为两类：
  - 关键版本：强制更新
  - 普通版本：允许稍后更新
- 未发现更新时应静默处理。
- 更新失败时应提示用户重试或稍后再试。

### 7.8 桌面待办提醒
- 仅待办类、需要处理类消息允许触发桌面弹窗。
- 普通通知、已读通知、纯抄送类消息不弹桌面提醒。
- 桌面提醒框位于 Windows 桌面右下角。
- 提醒框至少包含：
  - 标题
  - 简要内容
  - 关闭标志
  - 立即处理按钮

### 7.9 立即处理
- 点击关闭标志后，仅关闭本次提醒。
- 点击“立即处理”后，应复用 OA 现有“进入项目”跳转规则。
- 如果当前登录态有效，应直接进入对应业务页面。
- 如果当前登录态失效，应先进入登录页，登录成功后自动跳转到目标业务页面。
- 不允许绕过现有鉴权机制直接进入业务页。

## 8. 用户体验要求
- 桌面端应优先保持与现有 Web OA 的业务操作一致性。
- 桌面能力应尽量不改变现有页面结构与现有路由行为。
- 更新、错误、提醒、退出确认等反馈文案应简洁明确。
- 后台运行、托盘恢复、通知跳转等行为应稳定可预期。

## 9. 非功能要求
- 不改变现有后端鉴权模式。
- 远程页面必须与 Electron 主进程能力隔离。
- 桌面配置应保存在用户本地目录。
- 关键交互必须可恢复：
  - 地址改错可恢复默认
  - 更新失败可重试
  - 通知跳转失败可回到主窗口

## 10. 一期验收口径
一期验收至少覆盖以下结果：
- 可生成 Windows `.exe` 安装包
- 可正常安装、启动、关闭、卸载、重装
- 默认可连接现有 OA 前后端地址
- 登录、上传、下载、导出、通知等主流程可用
- 开机自启默认开启且可关闭
- 托盘常驻与关闭行为正常
- 窗口大小和位置可记忆
- 管理员可修改 OA 地址，普通用户不可修改
- 启动时可检查更新，支持普通与关键版本差异化处理
- 新待办消息可触发桌面提醒
- 立即处理可跳转至对应业务页，并在登录过期时支持登录后继续跳转
