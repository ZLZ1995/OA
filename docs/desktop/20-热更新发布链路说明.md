# 热更新发布链路说明

## 1. 当前方案
桌面端自动更新采用：

1. `electron-builder`
2. `electron-updater`
3. Windows `nsis`
4. `generic` 更新源

客户端启动后会自动检查更新，菜单“帮助 -> 检查更新”可手动触发。

## 2. 更新源要求
更新源目录至少需要以下文件：

1. `latest.yml`
2. `zhongqin-oa-setup-x.y.z.exe`
3. `release.json`
4. `zhongqin-oa-setup-x.y.z.exe.blockmap`（可选）

客户端通过安装包内的 `app-update.yml` 读取更新源地址，再从该地址拉取 `latest.yml`。

### 2.1 blockmap 发布策略
Windows `nsis + electron-updater` 场景下，`.blockmap` 主要用于差量更新。

当前正式规则如下：

1. `blockmap` 上传成功：客户端优先走差量更新
2. `blockmap` 上传失败但 `latest.yml`、`release.json`、`.exe` 可访问：不阻塞发布
3. 缺少 `blockmap` 时，允许客户端退回整包下载更新
4. 只有在 `latest.yml` 或 `.exe` 不可访问时，才判定本次更新不可上线

## 3. 版本规则
当前桌面端建议按以下规则发版：

1. `0.1.x`：桌面端初始化阶段的小修复
2. `0.2.0`：首次正式接通热更新链路，并同步当前线上 OA 的桌面内置前端版本
3. `0.2.1`：热更新链路整包升级演练版本，用于验证“发现新版本 -> 下载整包 -> 重启安装”完整流程
4. 之后遵循语义化版本：
   - 主版本号：重大重构或不兼容变更
   - 次版本号：功能增强、桌面能力扩展、内置前端大版本同步
   - 修订号：问题修复、样式优化、非破坏性补丁

说明：

1. 桌面应用显示名仍保留《中勤评估业务OA系统》
2. 仅热更新产物文件名改为 ASCII，避免 Zeabur 静态文件链路对中文路径返回 `404`

## 4. 本地验证地址
当前正式更新源采用：

`https://zhongqinoa.zeabur.app/desktop-updates/win/stable/`

如需本地联调，可临时改回本地地址。

## 5. 打包命令
在 `desktop/` 目录下执行：

```powershell
npm.cmd run publish:local
```

该命令会完成：

1. 编译桌面端与内置前端
2. 生成 NSIS 安装包
3. 生成 `latest.yml`
4. 复制更新所需产物到 `desktop/out-update-publish/`

## 6. 输出目录
本地验证产物目录：

`desktop/out-update-publish/`

正式构建目录：

`desktop/out-update-release/`

## 7. 正式发布步骤
1. 递增版本号
2. 执行 `npm.cmd run publish:official`
3. 优先上传 `out-update-publish/` 下的 `latest.yml`、`release.json`、`.exe`
4. 若 `.blockmap` 上传成功，一并发布；若连续上传失败，可先跳过，不阻塞上线
5. 将发布成功的文件上传到 `https://zhongqinoa.zeabur.app/desktop-updates/win/stable/`
6. 用已安装旧版客户端执行“检查更新”

## 8. 验证标准
1. 安装包内存在 `app-update.yml`
2. 发布目录存在 `latest.yml`
3. 发布目录存在 `release.json`
4. 手动检查更新时：
   - 无更新会提示“已是最新版本”
   - 有更新会提示是否下载
   - 下载完成会提示重启安装
5. `.exe` 返回 `200 OK` 时，可判定整包更新链路可用
6. `.blockmap` 缺失不影响整包更新上线，但会失去差量更新能力
7. 更新失败不会导致主程序崩溃

## 9. 风险边界
1. 仅桌面端产物可通过该链路更新
2. 后端改动仍需单独部署
3. 版本号不递增时，客户端不会识别为新版本
