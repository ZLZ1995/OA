# 账号注销交接与项目冲突优化方案

日期：2026-10-20。实施基线：25d9189。

## 业务规则

- 停用/删除账号时，未完成项目的创建人、负责人职责自动交给执行操作的管理员；审核及其他指定办理职责进入管理员待分配清单。管理员可继续办理项目方事务或转交有效账号。
- 当前系统创建项目接口允许全部已登录有效账号，因此创建人接任候选采用同一口径，不额外限制为 SALES。审核等专职职责仍检查对应角色及项目回避。
- 已归档、已终止、已删除项目不交接。历史创建、审批、附件身份通过原始记录与新增交接审计保留。
- 不改变工单阶段；其他有效审核人的当前任务不因项目方交接被抢占。
- 不冲突决定对同一对项目、同一业务依据持续生效；人员交接不属于判重依据变化。

## 实施

1. 新增交接任务及审计表、管理员列表/候选/分配接口，接入账号删除和停用入口。存量停用账号提供只读预览和显式接管操作。
2. 同步项目方权限、工单负责人、成员及当前办理人；审核任务由管理员重新指定合格人员，不自动授予管理员专业审核角色。接管及分配留痕并通知。
3. 新增按项目对和业务指纹唯一的判重依据表。读取流程不再创建冲突；相关写操作内检测。旧判定和同对重复提醒提供兼容及归并，保留旧记录。
4. 管理端显示待接管及历史交接记录；项目冲突处理显示剩余提醒，保留项目不再等待另一个项目删除才解除该对冲突。
5. 回归验证账号停用/历史接管、重分配/回避、终态排除、历史保留、查询无副作用、不冲突幂等及并发唯一约束。

## 发布与恢复

新增表兼容现有结构，支持启动 create_all 和 Alembic 迁移。先备份数据库再部署；存量项目通过管理员预览清单逐项接管。不得批量改历史审批人、附件上传人，不删除旧项目资料。只有生产目标账号完成业务操作后才能确认具体项目恢复。

客户相似度算法改版和跨项目附件合并不在本轮实施范围；保留当前检测阈值，优先解决判定失效、交接缺失及状态一致性。

判重不再因两项目创建人相同而跳过，以免管理员接管多个项目改变检测结果。旧版本提醒的快照并非不可变历史证据，首次升级依据现存快照归并旧判定；管理员应复核曾修改金额、客户或基准日的历史项目。新判定依据单独保存，旧版本待处理提醒不得用于处理已变化的业务依据。

## 验证与上线边界

使用隔离测试数据库验证交接、权限校验、历史保护、重复提醒判定与迁移幂等；生产数据库和具体受影响项目尚未操作。上线前备份，发布前后端；管理员在“项目接管与交接”核对并逐项接管存量项目，再由接任账号验证当前节点。不要通过新建同名项目规避旧项目权限问题。
